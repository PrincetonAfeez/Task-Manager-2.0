# Audit Pass 2 — Domain Correctness and Data Integrity

> "This is an enterprise-grade, production-ready SaaS Product. Analyze the code, identify all
> bugs, errors, gaps, and inconsistencies, and document the corresponding fixes. Give me a
> definitive, finite list."

Scope of this pass: the promises the domain model makes and whether the code keeps them.

| # | Severity | Finding | Evidence | Fix |
|---|----------|---------|----------|-----|
| 2.1 | Critical | **The durable queue had no runtime.** `Job` rows accumulated forever; the only Celery task was `{"status": "placeholder"}`. Every reminder, notification and webhook the product claimed to send was silently never sent. | `queues/tasks.py:4-6` (original) | Built `queues/registry.py` (handler registry), `queues/runtime.py` (claim → attempt → complete/fail loop), `queues/handlers.py` (seven real handlers) and real Celery entry points. |
| 2.2 | Critical | **Enqueue was not actually idempotent.** The reminder key was `f"reminder:{task.id}:{reminder_at.isoformat()}"` where `reminder_at = max(timezone.now(), …)` — for any past-due task the key contained `now()` and changed on every call, so retries created duplicate jobs. | `tasks/services.py:83-89` (original) | `schedule_reminder` now derives the key from the *reminder instant* rounded to whole seconds, and cancels superseded reminders. Covered by `test_queues.py::TestIdempotency`. |
| 2.3 | Critical | **No lease expiry / reaper.** `Job.lease_expires_at` existed but nothing ever read it. A worker killed mid-job stranded that job permanently. | `queues/models.py:60` with no consumer | `reap_expired_leases()` returns stalled jobs to the pool or dead-letters them when the attempt budget is gone. `ops.views.reaper_healthz` now reports real stranded-lease counts. |
| 2.4 | High | **No retry/backoff/dead-letter path.** `max_attempts`, `next_retry_at` and the `DeadLetter` model were all inert. A failing job had no defined behaviour at all. | `queues/models.py:62-63`, `queues/models.py:108` | Exponential backoff with jitter (`retry_delay_seconds`), permanent-vs-retryable error classification, dead-lettering on exhaustion, and operator redrive. |
| 2.5 | High | **The scheduler did not exist.** `Schedule.next_run_at` was never advanced and `ScheduleOccurrence` rows were only ever created by tests. Schedules displayed a preview and did nothing. | `schedules/services.py:1-23` (original — only `preview_next_runs`) | `scan_due_schedules` / `fire_schedule` materialise occurrences and enqueue jobs, with the unique `(schedule, scheduled_time)` constraint as the double-fire guard. |
| 2.6 | High | **Cron was evaluated in the wrong timezone.** `preview_next_runs` used `croniter(expression, timezone.now())` and ignored `Schedule.timezone` entirely, so "09:00 daily" fired at 09:00 UTC for every tenant and drifted an hour across DST. | `schedules/services.py:13-15` (original) | Every evaluation converts to the schedule's own `ZoneInfo` first, then back to UTC. Covered by `test_schedules.py::TestTimezoneHandling`. |
| 2.7 | High | **Catch-up policy was declared but unimplemented.** `CatchUpPolicy` had three values and no code read them; a scheduler outage would have replayed unbounded work on restart. | `schedules/models.py:24-27` (original) | `_due_instants` implements SKIP / RUN_ONCE / RUN_ALL, bounded by `SCHEDULE_CATCH_UP_MAX_OCCURRENCES`. |
| 2.8 | High | **Recurrence was parsed and thrown away.** `parse_quick_add` extracted `daily|weekly|monthly` into `QuickAddResult.recurrence`, and `create_task_from_quick_add` never looked at it. `RecurrenceRule` had zero writers anywhere in the codebase. | `tasks/quickadd.py:47` vs `tasks/services.py:52-89` (original) | Added `tasks/recurrence.py` with a real engine (interval, weekday sets, month-end clamping, until/max bounds) wired to both completion and a nightly sweep. |
| 2.9 | High | **`Task.position` was never assigned.** Every task was created with `position = 0`, so the board had no stable ordering and drag-and-drop had nothing to write to. | `tasks/models.py:78` default `0`, no writer | Sparse fractional positioning (`POSITION_STEP`), `next_position()`, `position_between()` and an O(n) `renumber_column()` escape hatch when the gap collapses. |
| 2.10 | High | **`Task.version` was an unused field.** The optimistic-concurrency token incremented on complete/reopen but nothing ever *checked* it, so two concurrent editors silently overwrote each other. | `tasks/models.py:79` | `_check_version` raises `ConcurrentModification` → HTTP 409 on the API and an HTMX flash in the UI. Covered by `test_tasks.py::TestOptimisticConcurrency`. |
| 2.11 | Medium | **`Task.Meta.ordering` sorted by `status` as a string**, giving `archived < completed < open` — archived work appeared at the top of every list. | `tasks/models.py:82` (original) | Ordering is now `-priority`, `due_date` (nulls last), `position`, `-created_at`. |
| 2.12 | Medium | **`Column.organization` could contradict `Column.task_list.organization`.** Both were writable and nothing reconciled them, so a column could be filed under tenant A while its list belonged to tenant B. | `tasks/models.py:64-65` (original) | `Column.save()` derives the organization from the list; `Column.clean()` rejects a mismatch. Same guard added to `TaskList.project_area` and `Job.queue`. |
| 2.13 | Medium | **A task could reference a column from a different list**, which hides the card on every board. | no validation anywhere | `Task.clean()` and `TaskSerializer.validate()` reject the mismatch; `move_task` re-checks. |
| 2.14 | Medium | **`due_time` without `due_date` was accepted**, producing a task due at "17:00" on no particular day. | `tasks/models.py:75-76` | Database `CheckConstraint` `task_due_time_requires_date` plus form and serializer validation. |
| 2.15 | Medium | **`status=completed` with `completed_at=NULL` was representable**, breaking every cycle-time calculation. | no constraint | `CheckConstraint` `task_completed_requires_timestamp`. |
| 2.16 | Medium | **No effect-idempotency was ever claimed.** `EffectMarker` existed with no callers, so an at-least-once queue would have sent duplicate emails on every retry. | `queues/models.py:118` with no writer | `claim_effect()` takes the marker inside the effect's transaction; used by the email and digest handlers. The email handler releases the marker on SMTP failure so a retry is not silently skipped. |
| 2.17 | Medium | **Interval schedules drifted.** There was no interval anchor, so each fire scheduled the next one relative to *when the scan happened*, accumulating the scan latency every cycle. | `schedules/services.py:17-27` (original) | Intervals advance in whole steps from a fixed anchor (`last_run_at` or `created_at`). |
| 2.18 | Medium | **Invalid cron expressions were never validated** and would raise inside the request that rendered the preview. | no validation on `Schedule.expression` | `validate_expression()` runs in the model's `clean()`, the form and the serializer; three consecutive evaluation failures deactivate the schedule instead of retrying forever. |
| 2.19 | Medium | **Quick-add silently dropped text.** `TIME_RE` matched `1-12` with an optional `am/pm` group that was actually required, `LABEL_RE`/`MENTION_RE` had no length bounds, and a title consisting only of modifiers fell back to the raw string including the modifiers. | `tasks/quickadd.py:8-11, 60` (original) | Rewritten parser: bounded input, 24-hour times, weekday names, `in N days`, ISO dates, deduplicated labels, and a documented "never lose the user's text" rule. |
| 2.20 | Medium | **`combine_due_datetime` used `timezone.make_aware`**, which raises on ambiguous and non-existent local times — a task due 02:30 on a DST spring-forward night crashed the request. | `tasks/quickadd.py:64` (original) | Attaches `ZoneInfo` directly so fold rules resolve it. |
| 2.21 | Medium | **Reminders were never cancelled.** Completing, archiving or rescheduling a task left the armed reminder and its job in place, so users got reminders for finished work. | no cancellation path | `cancel_reminders()` disarms the reminder and cancels the job; called from complete, archive, move-to-done and due-date change. |
| 2.22 | Medium | **`Subtask`, `Comment` and `ListMembership` were unreachable.** No view, no API route, no template rendered them. | absent from `api/urls.py` and `web/urls.py` (original) | Full CRUD across the web UI and API, with notifications on comment. |
| 2.23 | Low | **`SavedView` had no writer or reader**, and `Notification.natural_key` had no documented meaning despite carrying a unique constraint. | `kernel/models.py:96` | Saved views are now created/applied from the task list; `natural_key` is documented as the idempotency barrier and used as such. |
| 2.24 | Low | **`Organization.timezone` was a free-text field** with no validation; a typo silently broke every schedule in the workspace. | `kernel/models.py:14` | `Organization.clean()` validates against `zoneinfo`; the form offers a curated list. |
| 2.25 | Low | **Dependency cycles were representable.** Nothing prevented A-blocks-B-blocks-A, which would deadlock both tasks forever. | model did not exist | `TaskDependency` with a DB check against self-blocking and an iterative cycle walk in `add_dependency`. |

## Verification

`tests/test_queues.py`, `tests/test_schedules.py`, `tests/test_recurrence.py` and
`tests/test_tasks.py` assert each behaviour above, including the negative cases
(duplicate enqueue, expired lease, DST boundary, cycle rejection).
